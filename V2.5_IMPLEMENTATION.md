# Agentic-AI V2.5

## Runtime boundary

- **System 1** is the authoritative control plane.
- **System 1 providers** may include the built-in guard plus configured OpenAI, Google Gemini, and Anthropic adapters.
- **System 2** is local-only. Built-in reasoning and registered OpenAI-compatible local servers are restricted to loopback addresses.
- System 2 can propose; it cannot directly execute tools or bypass permissions.
- Execution remains under the planner, risk/permission engine, executor, observer, verifier, evaluator, recovery and persistence layers.

## Backend

`backend/app/` contains the agent kernel and control plane:

- `main.py` — FastAPI application and task/agent/memory/regression APIs.
- `agent.py` — agentic loop and System 1/System 2 boundary.
- `model_adapter.py` — built-in/local/remote model adapters and runtime routing.
- `model_manager.py` — persistent JSON registry for local System 2 models and System 1 council policy.
- `system1_council.py` — any/all/consensus decision layer and fail-closed handling.
- `local_discovery.py` — loopback discovery for LM Studio, Ollama, llama.cpp and vLLM.
- `brain_routes.py` — model manager, discovery, policy and council HTTP API.
- `planner.py` — dependency-aware plans/DAGs.
- `tool_registry.py` — tool risk and authorization policies.
- `executor.py` — controlled execution, timeout/retry/cancellation.
- `observer.py` — execution trace/event stream.
- `verifier.py` — deterministic verification.
- `evaluator.py` — deterministic/judge/human evaluation.
- `memory.py` and `storage.py` — persistent memory and SQLite history.
- `regression.py` — golden dataset and regression runs.

## Frontend

The React/Vite frontend is a dark AI-core control center with:

- runtime boundary dashboard
- agent goal composer
- System 1 provider cards
- council policy: any/all/consensus
- minimum confidence
- minimum review count
- fail-closed switch
- System 2 model activation
- loopback model registration
- local server discovery and latency display
- task/run history
- responsive mobile layout

## Run

Backend:

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Frontend:

```bash
cd frontend
npm install
npm run dev
```

Open the Vite URL shown by the terminal. The frontend expects the backend at `http://localhost:8000`.

## Provider security

Never put provider API keys in frontend code, the model registry, or Git. Keep keys in the backend process environment. System 2 registration rejects non-loopback URLs.
