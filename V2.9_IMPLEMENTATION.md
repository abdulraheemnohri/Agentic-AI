# V2.9 — Live Async Execution + Unified Backend Control

V2.9 turns Agentic-AI execution into an asynchronous service and exposes a live browser observatory.

## Architecture

```text
Browser / React Observatory
          |
          v
Integrated FastAPI :8000
  |               |
  |               +--> System 2 lifecycle (local-only, frontend controlled)
  +--> AgentKernel background task
          |
          +--> System 1 Council / permission gate
          +--> Executor -> Observer -> Verifier -> Evaluator -> Memory

Dedicated service ports remain available:
System 1 :8101 (always-on)
System 2 :8102 (frontend-controlled)
```

## Async agent API

`POST /api/agent/run` now returns HTTP `202` immediately:

```json
{
  "accepted": true,
  "run_id": "...",
  "task_id": "...",
  "run": { "status": "..." },
  "task": { "status": "planned" },
  "message": "Agent run accepted; execution continues asynchronously."
}
```

The server creates an asyncio background task. Progress is persisted through the existing agent-run and SQLite storage path.

### Live status

`GET /api/agent/{run_id}/async-status` returns `active`, status, run state and task state.

The existing trace endpoint remains available:

`GET /api/agent/{run_id}/trace`

Cancellation continues through:

`POST /api/agent/{run_id}/cancel`

## Security boundary

- System 1 remains authoritative.
- System 1 is automatic/always-on; the frontend has no System 1 stop action.
- System 2 remains local/loopback-only.
- System 2 can be started, stopped, restarted, updated or upgraded only through the frontend-controlled lifecycle.
- System 2 cannot authorize execution or modify System 1.
- Remote System 2 update URLs are rejected.
- Agent execution still requires the System 1 Council decision plus tool permission checks before execution.

## Frontend

A standalone live page is available at:

`http://127.0.0.1:5173/async-observatory.html`

It provides:

- asynchronous run launch
- 900 ms live polling
- status/phase/run/task IDs
- event stream
- cancellation
- backend state
- System 2 lifecycle controls
- explicit System 1 authority boundary

The existing V2.8 Observatory and `backend-control.html` remain available.
