# V3.0 — Production Local Agent Runtime

V3.0 turns the V2.9 asynchronous execution foundation into a unified local control plane.

## Architecture

```text
                 React V3 Control Plane
                         |
                    FastAPI :8000
                         |
          +--------------+---------------+
          |              |               |
     Agent Runtime   System 1        System 2
     queue/semaphore authoritative   local-only
          |              |               |
          +------ AgentKernel ----------+
                         |
              Council -> Permissions
                         |
        Executor -> Observer -> Verify
             -> Evaluate -> Memory
```

## Backend

### Execution runtime
`backend/app/runtime.py`

- persistent runtime configuration
- concurrency semaphore
- bounded queue
- active/queued counters
- completed/failed/cancelled telemetry
- duplicate job protection
- local-only execution

Configuration is stored in `backend/data/runtime_config.json`.

### Runtime API
`backend/app/runtime_routes.py`

- `GET /api/runtime/status`
- `GET /api/runtime/config`
- `PUT /api/runtime/config`
- `GET /api/runtime/active`
- `GET /api/runtime/events/{run_id}` (SSE)

### Async Agent
`backend/app/async_agent_routes.py`

- `POST /api/agent/run` → HTTP 202
- background AgentKernel execution
- persistent progress
- cancellation compatibility
- runtime queue integration
- `GET /api/agent/{run_id}/async-status`

### Security
- System 1 remains authoritative.
- System 1 remains automatic/always-on.
- System 2 is local/loopback-only.
- System 2 cannot authorize execution.
- System 2 cannot stop or modify System 1.
- Execution requires both System 1 Council approval and tool permission.
- Remote System 2 update URLs remain denied.

## Start

```bash
cd backend
python -m backend.app.server
```

In another terminal:

```bash
cd frontend
npm install
npm run dev
```

Open `http://127.0.0.1:5173`.
