# V3.1 — Production Runtime, Recovery, Audit & Unified Control Center

## Runtime

The local execution runtime accepts asynchronous AgentKernel jobs, applies a configurable concurrency limit and bounded queue, and exposes runtime telemetry through `/api/runtime/*`.

## Recovery

`RecoveryManager` persists runtime job state and audit events in SQLite. Recoverable states are discoverable after a process restart. Recovery bookkeeping is intentionally separate from the reasoning model.

## Live transport

`/api/runtime/events/{run_id}` provides Server-Sent Events using the persisted run stream. `/api/observability/events` provides a process-wide runtime event bus.

## Security

System 1 is the authoritative control plane and remains always-on. System 2 is local/loopback-only, frontend-controlled, and has no authority. Forbidden System 2 authority operations are rejected. Execution continues to require System 1 Council authorization followed by tool permissions.

## Supervision

A System 1-owned health supervisor checks the AgentKernel/store path and exposes `/api/security/system1-health`. It does not delegate authority to System 2.

## Frontend

V3.1 promotes `frontend/src/v31.tsx` to the main Vite entry. The control center includes Dashboard, Agent, System 1, System 2, Runtime, Tasks, Memory, Evaluations, Tools, Audit, Security and Settings views, with responsive dark AI-core styling.

## Start

```bash
cd backend
python -m backend.app.server

cd ../frontend
npm install
npm run dev
```

The primary UI is `http://127.0.0.1:5173` and the API is `http://127.0.0.1:8000`.

## Validation

```bash
cd backend
pytest -q
cd ../frontend
npm run build
```
